# 稳定确认版

本目录中的 `main.py` 和 `minimain.py` 是可分别独立部署的稳定确认版：

- `main.py`：主车，上传为主车 SD 卡的 `/sd/main.py`。
- `minimain.py`：从车，上传为从车 SD 卡的 `/sd/main.py`。

仓库根目录的同名文件保持为原有快速版。本目录只加强首次锁定确认，
不再要求主控先发送命令才能启动模型识别。

## 首次锁定规则

1. 程序启动后立即运行模型候选搜索，不依赖 `0x02`，也没有额外的 `300 ms` 等待门槛。
2. 未正式锁定时，模型候选统一使用 `0.30` 的最低置信度，只把置信度作为有效门槛，不参与目标远近竞争。
3. 候选使用模型框底边接触点换算出的世界距离排序，严格优先确认最近的有效、未完成目标。
4. 首次锁定最多观察 `7` 个真实模型推理帧；同一类别、相近中心和相近大小累计达到 `5` 帧就立即确认。稳定目标因此在第 `5` 帧锁定，出现 `1`～`2` 帧漏检时才延长至第 `6`～`7` 帧；高置信度也不能单帧锁定。
5. 复检期间出现更近候选时，远候选的确认立即作废并从更近候选重新计数。
6. 复检通过前持续发送无目标包；通过后才建立正式模型锁并上报 ID 和世界坐标。
7. LAB 动态颜色确认保持根目录默认版的 `3` 帧；模型保持帧不能计入首次锁定的 `5/7`。
8. `0x02` 和 `0x00` 仍用于清空当前目标并重新搜索，但不再负责开启识别权限；同一阶段重复发送的 `0x02` 不会反复清空 `5/7` 计数。

按每秒 `20` 个真实模型推理帧计算，稳定目标从首次检测到正式锁定约为 `0.20 s`（完整占用 `5` 帧约为 `0.25 s`）；若中间漏检一帧或两帧，则分别约为 `0.25 s` 或 `0.30 s`。

黄线、`0x06` 全色块扫描、已完成 ID 排除和 UART 数据包格式与根目录当前版一致。

## ID2 首目标优先

每次上电或收到 `0x08` 清空完成状态后，普通目标搜索、LAB 确认、主控 `0x03,id` 锁色和世界坐标输出都只允许 ID2。ID1、ID3、ID4、ID5 即使更近或置信度更高也不会建立目标锁或上报。

主车确认 ID2 越过黄线、从车在对应搬运结束的下一次 `0x00/0x02` 提交 ID2 后，ID2 完成位生效，其余所有未完成 ID 同时开放并恢复正常最近目标竞争。重启或 `0x08` 会清空该完成位并重新回到 ID2 优先阶段。`0x06` 仍是独立的全色障碍扫描，不使用这个优先门控。

## 启动曝光

上电后从 SD 卡根目录 `/sd/color_thr.txt` 的 `exposure_us=` 行读取固定曝光并关闭自动曝光。仓库当前 [color_thr.txt](../color_thr.txt) 的值为 `1200 us`。配置缺失或数值无效时回退为 `1400 us`，有效范围保持为 `100～4500 us`；颜色阈值和地面阈值仍按原逻辑从同一文件加载。

## 主控指定颜色

收到有效的 `0x03,id` 表示另一块 OpenART 已经完成严格颜色判定，因此本机把主控 ID 作为目标选择结果。本机 LAB 不再重新决定目标 ID，但仍负责把具体颜色和模型框对应起来，防止共用模型类别的两个颜色锁到不同物体。未指定颜色时仍使用上述严格规则。

- 本机只搜索指定 ID 对应的模型类别，并要求模型框内最接近的颜色就是指定 ID；不再要求自动识别使用的 `60` 距离优势。
- 指定模式使用最低 `0.25` 模型置信度，在最多 `5` 帧内命中 `3` 帧就建立模型锁。
- 指定模式允许中心移动 `36 px`、框宽高变化 `50%`；未指定模式仍为 `24 px`、`35%`。
- 指定模式的 LAB 最大 IQR 放宽为 `(65, 70, 85)`；3 次模型命中都必须对应指定颜色，建立模型锁后不再额外等待动态颜色确认。
- 模型类别不一致、模型框更接近同类别的另一颜色、ID 已完成或尚未通过 ID2 首目标门控时仍拒绝。
- 如果切换到另一个 ID，即使两个 ID 共用同一模型类别，也不会把旧颜色框直接当成新目标继续使用。

## 清空搬运完成状态

主控发送四字节帧 `AA 55 08 08` 后：

- ID1..ID5 的完成 mask 清零，普通目标搜索重新只开放 ID2。
- 当前 `0x03` 单色锁、模型锁、色块跟踪和前扫状态被清除。
- 从车额外清除尚未提交的待搬运 ID。
- 清零后立即恢复 ID2 搜索，并重新执行 ID2 的首次确认。
- 曝光、LAB 标定阈值和动态学习阈值不会被清除。
