# OpenART 双车视觉系统

当前代码状态：**`main` 分支，2026-08-16 现场调试版**。

- 主从均使用 `/sd/80lite0.5V57.tflite`、固定白平衡 `(92,64,101)` 和默认曝光 `880 us`；`/sd/color_thr.txt` 可覆盖白平衡与曝光。
- `ID2_ABSOLUTE_PRIORITY=False`，上电默认搜索所有未完成 ID；主控可用 `0x0C` 在运行时切换红砖优先、网球优先及分阶段策略。
- `ENABLE_COMPLETED_COLOR_EXCLUSION=True`，搬运完成的 ID 退出后续搜索，`0x08` 清空完成记录。
- 主车使用五段 ROI、自适应 LAB 阈值和动态侧扫速度判断黄线；当前为排障临时开启 SD 日志与搬运照片。
- 同色多目标使用 `0x09` 枚举、`0x0A` 确认；世界坐标通过 28 点网格解算并以毫米发送。

历史版本、参数演进和标定记录见 [中文更新日志](README_ch.md) 与 [English changelog](README_en.md)。

## 工程概览

这是全国大学生智能汽车竞赛双车接力方案的**视觉侧**仓库。每辆车由两块板组成：NXP RT1021 底盘主控负责运动控制与任务调度（代码在独立工程维护，不在本仓库），OpenART Plus 视觉板运行本仓库脚本，负责物块识别与世界坐标解算。视觉板作为主控的 UART 从设备（两车均为 `UART12`、`115200 bps`）：接收主控的命令帧（`0xAA 0x55` 帧头 + 单字节命令码 + 参数 + 校验和，如 `0x03` 指定颜色、`0x06` 全色前扫、`0x08` 清零完成记录、`0x09` 枚举同色候选、`0x0A` 确认候选、`0x0B` 启用 orbit 近场裁切），持续回发 16 字节坐标包；处理 `0x09` 时另以 12 字节 `0xC9` 包回传候选，所有世界 X/Y 均以**毫米**发送。

双车角色：主车运行 `main.py`，负责搬运全流程，含越过黄线记完成、回库黄线引导；从车运行 `minimain.py`，为搬运从机，搬运结束后提交待完成 ID。两份入口为各自车辆的固定入口（不再保留 `IS_SLAVE_CAR` / `SLAVE_MODE` 开关），检测管线一致：TFLite 模型负责发现、类别确认和重捕，动态 LAB 色块负责确认目标并提供中心位移，模型拥有的显示 / 坐标几何随该位移移动，平滑后的底边接触点再送入 28 点地面网格解算世界坐标。

## 搜索优先策略

`main.py` 与 `minimain.py` 顶部的 `ID2_ABSOLUTE_PRIORITY` 当前均为 `False`，因此上电后所有未完成 ID 按世界 Y 最近目标竞争。设为 `True` 时，上电默认只搜索 ID2，ID2 完成后再放开其他 ID；场上没有 ID2 时不会自动降级。

主控可发送 5 字节命令 `AA 55 0C FLAGS CHECKSUM` 动态切换策略，`CHECKSUM=(0x0C+FLAGS)&0xFF`：

| `FLAGS` | 策略 |
| --- | --- |
| `0x00` | 所有未完成 ID 自由竞争 |
| `0x01` | ID2 完成前只搜索 ID2 |
| `0x02` | ID3 完成前只搜索 ID3 |
| `0x05` | ID2 优先，随后 ID3/ID4/ID5，最后 ID1 |
| `0x06` | ID3 优先，随后 ID4/ID5，最后 ID1/ID2 |

策略只改变可搜索掩码，不清除完成记录；`0x08` 清空完成记录后按当前策略重新计算。`0x06` 全色前扫不受搜索优先掩码限制。

## 已完成颜色排除开关

主从入口顶部的 `ENABLE_COMPLETED_COLOR_EXCLUSION` 默认为 `True`。已完成颜色立即退出普通搜索和主控指定，下一阶段只从当前策略允许的未完成颜色中选择。`0x08` 清空完成位。

主车收到 `0x01` 进入搬运时锁存本次物体 ID。黄线过线退出的同一帧使用该锁存 ID 写入完成位，随后立即清空 `pending_carry_color_id`、`target_color_id`、主控指定标志以及模型/颜色跟踪状态。完成标记只校验 ID 范围，不依赖可能在搬运过程中变化的搜索掩码，因此 ID3 优先完成后会直接重建下一阶段掩码，不会继续以旧 ID3 限制模型类别。

从车同样在 `0x01` 时锁存搬运 ID，并在 `0x02/0x00` 完成时只使用该锁存 ID。没有有效锁存值时不得把当前搜索目标记为完成，避免普通复位命令提前跳过优先颜色。完成位写入不依赖搜索掩码，之后沿用原有命令处理清除目标跟踪状态。

设为 `False` 后仍会记录 `completed_color_mask`，但完成颜色继续参与候选；再次开启会立即按现有记录恢复排除。若希望从第一轮起所有颜色都参与竞争，还需要同时设置 `ID2_ABSOLUTE_PRIORITY=False`。

## 主车搬运黄线

`main.py` 使用 `y=90..109`、`110..129`、`130..149`、`150..169`、`170..189` 五段全宽 ROI。黄色 blob 可在相邻段或隔一段空间相连，单个 ROI 被物体遮挡不会立即切断轨迹；拟合从当前有效 blob 中选择纵向跨度最大的有效段对，减少只观察上方三段时的远距离外推。连续 2 帧形成连接即可确认见线。正常过线路径保持不变：有效拟合线到达 `YELLOW_BOTTOM_Y` 且具有下方连接或跨段证据时确认触底；触底后普通目标连续 2 帧没有有效拟合或侧扫证据即发送 `POS_CROSSED`。

针对黄线从进入画面起就接近竖直、始终无法满足 `YELLOW_MIN_FIT_DX` 的漏判，另有横向侧扫路径：在 `y=120` 跟踪相邻或隔一段连接的黄线。普通 `20 ms` 帧的跳变限制保持 `90 px`；相邻 ROI 的强连接按距离上一次有效候选的实际时间同比放宽，最大 `240 px`，隔一段连接不使用动态额度。这样 SD 写图、推理或 GC 造成慢帧时不会把真实黄线当作瞬移，同时普通帧仍拒绝远处伪候选。轨迹已经建立方向且至少丢失 1 帧后，原有同向 `200 px` 重接仍作为弱连接的回退。累计横移至少 `100 px` 后，最低两段 ROI 的相邻连接可直接确认黄线已经到达画面下部；原有距左右边缘 `52 px` 内稳定 3 帧的路径继续保留。确认触底后，有效拟合线或有效侧扫连接都会保持“黄线尚在”，两者都消失后才累计退出。进入搬运后的前 4 帧仍不累计退出。

搬运黄线首次进入仍使用配置中的固定 LAB 阈值。连续确认见线后，每隔 2 帧从当前最强黄线 blob 内、且仅限已被当前阈值判为黄色的像素计算 LAB 四分位范围，扩展 IQR 后以 `25%` 比例平滑更新自适应阈值；范围同时受固定阈值外扩上限约束，避免学习到地面或物块。自适应阈值无法形成相邻 ROI 黄线候选时，当帧立即用固定阈值重试，并用重试结果继续校正；自适应和固定阈值连续 2 帧都失效才清空学习结果。确认触底后冻结学习，避免退出阶段把背景逐步学成黄线。

ID3 网球搬运会保存并更新网球框。只有与网球框纵向相交的黄线 ROI 才按网球框左右各扩 `15 px`、上下各扩 `5 px` 后拆成左右两段检测，未相交 ROI 保持全宽。普通目标的拟合触底高度为 `210`，网球因高速通过且车体容易遮挡下方黄线，使用独立的 `190`；相邻 ROI 链接条件不变。黄线触底后，以 `y=120` 处的拟合交点跟踪运动：单帧跳变超过 `60 px` 或反向超过 `15 px` 的候选不再清空丢线计数；方向由至少 `4 px` 的首次有效位移建立。网球触底后的释放更快：有效拟合与侧扫证据都消失后，不再额外保持显示/发送，1 帧丢线即发送 `POS_CROSSED`。

网球靠近黄线底部时，下段 ROI 可能先被网球或车体遮挡。状态机保留最近 3 帧的跨至第 3 段或更低段的完整拟合与下方连接证据；若它连续退化为从第 1 段开始的较短拟合、拟合边缘没有超过 `12 px` 的反向跳变并越过网球底部门限，仍确认到线。孤立拟合、检测中断、反向跳变以及普通物体不会使用该桥接，`bottom_reason=4` 表示由此路径确认。

### 临时日志与照片

本轮黄线排障已临时将 `main.py` 中的 `ENABLE_MAIN_SD_LOG`、`ENABLE_YELLOW_FRAME_TRACE` 和 `ENABLE_CARRY_FRAME_CAPTURE` 全部设为 `True`，运行时会追加 `/sd/main_runtime.log` 并创建新的 `capNNN` 搬运照片目录。通用复现步骤如下：

1. 将上述三个开关设为 `True` 后部署到主车；只需要数值日志时可让 `ENABLE_CARRY_FRAME_CAPTURE=False`。
2. 清理或移走旧的 `/sd/main_runtime.log`，确认 SD 卡至少留有一个 `capNNN` 可用目录编号和足够空间，然后只复现一次异常搬运。
3. 复制 `/sd/main_runtime.log` 和最新的 `/sd/capNNN/`。日志采用 16 帧批量写入，并在 `POS_CROSSED`、丢线计数增加、触底状态变化时立即落盘；分析最近一个 `YELLOW_BEGIN` 后面的 `YF` 行。
4. `target_id/track_id/active_id` 确认当时搬运的是哪个 ID。
5. `entry_ev/bottom_ev/keep_ev/reached/bottom_confirm/bottom_reason` 判断是否被误判为见线、触底或持续保持；`bottom_reason` 为位掩码：`1` 表示拟合触底、`2` 表示侧扫到边缘、`4` 表示网球遮挡桥接、`8` 表示累计侧扫后连接到最低两段。
6. `top/mid/bot/low/lowest` 查看五段 ROI 的 blob 中心、像素、宽高，定位遮挡发生在哪一段；`pair=15` 表示使用第 1、5 段拟合。
7. `pair/fail/dx/dy/slope_x1000/b_x10/edge_y_x10/sweep` 判断拟合线和侧扫轨迹是否合理；`sweep` 依次记录候选 X、接受 X、起点、最小/最大 X、行程、边缘帧、间断帧、真实无候选帧、状态码、方向、候选 ROI 对、距上次有效候选毫秒数和本帧跳变限制。只有真实无候选帧可以授权原有方向重接；状态码 `1` 表示拒绝跳变，`3` 表示按既定方向成功重接。
8. `threshold` 依次记录来源、是否已有学习值、更新/回退/连续双失效次数、当前使用的 6 个 LAB 边界和学习后的 6 个 LAB 边界；`source=0/1/2` 分别表示首次固定阈值、自适应阈值和当帧固定阈值回退。
9. `lost/hold/pos` 判断是否因短暂丢线触发 `POS_CROSSED`。
10. 复现结束后立即把三个开关全部恢复为 `False`，避免 SD 写入降低帧率或耗尽空间。

## 同 ID 目标候选枚举与确认

当前 `main.py` 与 `minimain.py` 使用两阶段事务选择同色物体。旧的 `ENABLE_TARGET_ANCHOR_LOCK`、坐标 / 半径锚点状态及 11 字节 `0x09` 帧均已删除。`0x09` 只触发一次专用模型推理并保存候选快照，不会直接确认其中某个候选；主控收到完整候选列表后，再通过 `0x0A` 提交精确索引。

两种下行命令均为 6 字节：

```text
AA 55 09 CID SEQ CHECKSUM
AA 55 0A SEQ INDEX CHECKSUM
```

- `CID` 为要枚举的颜色 ID；它仍受 ID 范围、`ID2_ABSOLUTE_PRIORITY` 和已完成颜色排除开关约束。无效或当前不可搜索的 `CID` 不会启动枚举，也不会产生 `0xC9` 结果包。
- `SEQ` 为主控分配的单字节事务号。新的 `0x09` 会覆盖尚未确认的旧候选列表；`0x0A` 只有在 `SEQ` 与最近一次已完成枚举一致且 `INDEX` 有效时才生效。
- `INDEX` 从 `0` 开始。确认成功后，OpenART 以该候选的模型框和当次 LAB 颜色样本建立跟踪锁，并清空待确认列表；无效确认被静默忽略且没有专用确认回包，主控从后续常规 16 字节坐标包观察锁定结果。
- `CHECKSUM = (CMD + PARAM + VALUE) & 0xFF`，不包含 `AA 55` 和校验字节自身。

每个有效候选使用一个 12 字节上行包：

```text
AA 55 C9 SEQ INDEX TOTAL CID X_LO X_HI Y_LO Y_HI CHECKSUM
```

- `TOTAL` 是本次事务的候选总数，同一事务的所有包携带相同 `SEQ`、`TOTAL` 和 `CID`。候选按图像中的水平中心从左到右排序，因此索引在单次快照内稳定。
- X/Y 为 OpenART 当前 `box_to_world()` 坐标系下的 little-endian 有符号 `int16`，单位毫米。
- 没有候选时仍回发一个包：`INDEX=0`、`TOTAL=0`、X/Y 均为 0；主控不得对此发送 `0x0A`。
- `CHECKSUM = sum(C9..Y_HI) & 0xFF`。全部 `0xC9` 包发送完毕后，OpenART 还会按现有协议发送一帧 16 字节目标保持包或无目标包。

候选必须同时通过指定模型类别、主控指定搜索最低分数、LAB 颜色匹配、网球黄线过滤和有效世界坐标检查。普通 `0x03` 指定颜色、目标状态重置、回库或新的 `0x09` 都会使旧事务失效。RT1021 端必须按上述新长度升级；旧的 11 字节 `0x09` 锚点帧与当前解析器不兼容。

## Orbit 近场裁切与前方障碍扫描

主控在进入 orbit 时发送短帧 `AA 55 0B 0B`。OpenART 仅在已有有效选中目标时启用 `ORBIT_Y_CUT=140`：模型候选的底边必须到达 `y=140`，色块搜索 ROI 则与 `y=140..229` 的全宽区域取交集。重复 `0x0B` 幂等，不采集前五帧 ROI，也不改变坐标包时序。`0x01` 进入搬运、`0x02` 结束搬运、`0x07` 回库、目标重置、新的目标枚举或切换到其它目标都会解除裁切。

`0x06` 前方扫描不使用上述 orbit 裁切，仍扫描动态有效区域中 `y < 150` 的部分；扫描结束后，若尚未收到解除命令，普通目标跟踪继续使用 orbit 裁切。当前目标按 `IoU >= 0.20` 或中心距离 `<= 35 px` 排除，结果连续稳定 6 帧时发送，最多观察 12 帧，回包保持 `AA 55 C7 current_id mask count checksum`，其中 `count` 是不同颜色 ID 的数量。

前扫以模型结果为主，同时增加 ID2 色块补检。补检优先使用 `adaptive_color_thresholds[1]`，没有有效横砖时回退到基础 ID2 阈值；宽高比允许 `0.6..6.0`，并要求至少 70 个命中像素、`100 px²` 包围面积和 `0.40` 密度，因此即使模型不能识别横放红砖也能置位 ID2。棕熊与白熊共用模型标签，前扫和普通锁色都在模型内缩框中分别统计 ID4/ID5 固定阈值像素；获胜方至少 12 像素、领先至少 6 像素且达到另一方的 1.3 倍才确认，否则返回未知。动态熊阈值不参与身份竞争，只在整框统计与像素赢家一致时用于跟踪；不一致时使用固定阈值，避免背景样本强化错误身份。

## 世界坐标

- 标定源为 `ground_mesh_24_points_template.csv`，文件名沿用旧名，实际包含 `7 x 4 = 28` 个点。
- 图像链路固定为 QVGA、`vflip=True`、软件水平镜像、不使用 `lens_corr()`。
- 目标底边中点 `x + w/2, y + h - 0.5` 作为地面接触点。
- 模型刷新帧只在模型框内缩区域搜索颜色：左右各缩 `5%`、顶部缩 `5%`、底部缩 `10%`，并忽略旧颜色框引用。模型几何作为锚点；后续颜色框的尺寸变化不会改变坐标几何，只有颜色框中心位移会同步平移显示框和坐标框。
- 显示框和坐标框统一使用省赛冻结版的单级平滑：当前值 `70%`、上一值 `30%`；框中心移动超过 `36 px` 时当帧直接采用新框。唯一参数为 `OUTPUT_SMOOTH_ALPHA_X100=70` 和 `OUTPUT_SMOOTH_RESET_CENTER2=36*36`。
- 已删除独立坐标 EMA、接触点死区、近距离降权和跳变二次确认。锁定后的兼容模型候选首次推理即更新；任何距离下的新模型几何均参与同一 `70%` 跟随，不再因低分保持旧坐标。只有真实检测丢失时仍沿用既有的有限帧保持 / 重捕状态机。
- 网格内使用 36 个三角形插值，网格外使用全局单应矩阵回退。v1.1.0 起三角形扫描从上次命中的网格单元续扫（连续接触点几乎总在同一单元），插值结果与逐一扫描逐位一致。
- 板内坐标单位为厘米，16 字节 UART 包中的 X/Y 仍发送**毫米**。
- 主车继续保留 `8 s` 硬件 WDT 防死锁；它与已删除的 ID2 坐标 watchdog 日志无关。主从正式入口都不创建或写入 `id2_coordinate_watchdog.log`。

启动时应看到：

```text
[GROUND] loaded 36 triangles from /sd/camera_ground_mesh.txt
```

缺少或拒绝网格时只会使用精度较低的全局单应回退，不应作为正式部署状态。
