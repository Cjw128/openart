# OpenART 双车视觉系统

当前版本：**2026-07-16 现场自动标定与运行识别强化版（v0.10.0）**

本仓库用于双 OpenART Plus 智能车视觉系统。正式比赛仍采用主车、从车各自一个完整 Python 文件的部署方式；本次更新重点补齐了比赛现场自动标定、阈值复检、熊类区分、网球阴影抑制、动态地面裁切、搬运前避障扫描以及 OpenART 固件兼容性。

## 文件与职责

| 文件 | 部署位置 | 用途 |
| --- | --- | --- |
| `main.py` | 主车 `/sd/main.py` | 五色目标识别、动态地面裁切、黄线/过线状态、搬运前避障扫描和 16 字节世界坐标上报 |
| `minimain.py` | 从车 `/sd/main.py` | 五色目标识别、动态地面裁切、搬运前避障扫描、`0x07` 回库横向黄线检测和世界坐标上报；不执行主车搬运过线状态机 |
| `calib_ide_autocalib_competition.py` | OpenART IDE 运行 | 比赛现场自动曝光、双地面采样、五目标自动标定、模型/色块复检和运行预览 |
| `front_obstacle_scan_test.py` | OpenART IDE 运行 | 搬运前前方其它颜色扫描的独立画面预览与阈值验证 |
| `return_yellow_test.py` | OpenART IDE 运行 | 回库横线 Y 与停车黄线 X 的独立预览；读取板载曝光/蓝布阈值，动态裁切后绘制 ROI、检测线、`x=200` 门槛和 `0xC8` 状态 |
| `calib_ide_tune.py` | OpenART IDE 运行 | 旧版/辅助标定参数调试 |
| `color_thr.txt` | 示例 | `/sd/color_thr.txt` 的格式参考，不应代替每块相机现场重新标定 |

主车和从车当前均为 OpenART Plus，串口固定为 `UART12`、`115200 bps`。部署时要把 `main.py` 和 `minimain.py` 分别改名/上传为各自设备的 `/sd/main.py`，不要互换。

## 推荐部署流程

1. 将 `dataset_25000_exposure.tflite` 放入目标相机的 `/sd/`。
2. 在 OpenART IDE 中运行 `calib_ide_autocalib_competition.py`，确认启动日志为 `build: 2026-07-15 red-bag-bear-core-v21`。
3. 自动曝光和地面采样阶段保持赛道区域干净，不要让目标、手或场外物体遮住近/远地面采样带。
4. 按控制台提示依次完成五个槽位；每个目标通过采样和复检后再移走。
5. 确认控制台显示五个槽位完整，并已写入 `/sd/color_thr.txt`。
6. 主车上传 `main.py`，从车上传 `minimain.py`，两者在设备上均保存为 `/sd/main.py`。
7. 分别检查目标框、动态裁切、UART 数据、搬运前 `0x06` 扫描和回库 `0x07` 横向黄线，再进行整车联调。

每块相机的曝光、白平衡视角和地面颜色都可能不同，主车和从车应分别标定，不能默认共用另一块相机生成的文件。

## 自动标定操作顺序

自动标定当前使用固定阶段顺序：

1. 淡蓝沙包和红沙包，两个沙包可按任意先后顺序放置。
2. 网球。
3. 棕色泰迪熊。
4. 白色泰迪熊。

模型只识别 `bag / ball / bear` 大类，棕熊和白熊本身不由模型区分，因此两只熊必须遵守上述阶段顺序。上一目标完成后需完全移出画面，等待：

```text
[collect] swap clear 8/8
```

再放下一目标。任何可信目标重新出现都会重置清场计数，防止棕熊残留被写入白熊槽位。

### 自动曝光

- 全画面目标亮度为 `L_TARGET = 38`，相对原来的 `40` 下调 `5%`。
- 允许误差为 `±1`。
- 全画面亮度上四分位 `Luq >= 92` 时触发高光保护并继续降低曝光。
- 最终曝光会立即更新 `/sd/color_thr.txt` 的 `exposure_us` 行；完整颜色和地面配置只有在五个槽位全部成功后才正式覆盖。

建议最终日志接近：

```text
L=37~39
Luq<92
```

自动曝光结束后会立即改写正式配置中的 `exposure_us` 行，即使后续某个颜色没有通过复检。已有可用配置建议先备份；脚本会保留其中原有的地面和五色阈值，只替换曝光行。

### 双地面采样

标定脚本分别采集近处 `ground` 和远处 `ground2`：

- 地面 ROI 被拆成小块。
- 与模型目标框相交的小块不参与统计。
- LAB 中位数离群块会被剔除。
- `main.py` 和 `minimain.py` 加载后，对 `ground` 与 `ground2` 的六个 LAB 边界逐项取平均，作为动态裁切的地面阈值。
- 若只存在一组地面值，则回退使用现有的单组值。

### 模型框向 LAB 边界扩散

模型框只是目标核心提示，标定脚本会从模型框内部沿上下左右射线寻找 LAB 跳变：

- 射线会越过类别兜底扩框，再从外侧连续地面/背景反向确认真正边界。
- 多条射线需满足一致性，单条异常边不会直接扩张目标框。
- 不能可靠确认的边回退到按类别扩张的保守框。
- 熊类底边最多超过兜底框 `4 px`，防止把脚下长投影当成熊身体。

调试画面中：黄色为原模型框，蓝色为类别兜底框，青色为 LAB 修正框，绿色为实际统计 ROI。

### 分类取样策略

- **网球**：圆形目标不再使用接近整框的矩形统计，避免四角混入蓝地；使用中央核心区，并只在下部内缩条带通过地面、IQR 和核心色差检查时合并暗边。
- **沙包**：允许模型框外边带补样，但边带命中地面或与核心 A/B 差异过大时不会合并。
- **棕熊/白熊**：取样区裁掉扩散框最底部约 `10%`；棕熊 L 下界不低于本体中位数减 `14`，保留毛发暗部但排除极暗投影。
- **白熊**：保留黄白高光和灰色阴影所需的较宽 A/B 范围，同时与地面发生真实 A/B 重叠时使用 L 通道分离。

### 稳定采样与自动恢复

- 每个目标需要 `10` 个合格样本帧。
- 棕熊、白熊和红沙包在采样前都需要连续稳定模型框。
- 红沙包若从旧位置跳到一个新位置，新框连续稳定 `3` 帧后会自动重建基准，已有样本清零并从新位置重新计数。
- 清场被上一目标打断时，当前目标锁、红袋基准和未完成样本都会清空，避免换物过程混采。

### 模型/色块复检

每个新阈值不会立即保存，而要再通过 `10` 个模型有效帧复检。复检比较模型修正框与新阈值得到的色块框，检查：

- 模型存在但没有有效色块。
- 两个框完全不同、中心距离过大或重叠过低。
- 色块面积或宽高只剩模型框很小一部分。
- 色块吞入大块背景。
- 色块相对模型框的中心、宽高或面积连续突跳。

连续异常 `3` 帧、累计异常 `4` 帧或发生 `2` 次严重跳变时，本轮阈值作废并自动重新采样。失败阈值不会进入正式结果。

### 棕熊与白熊强制分离

棕熊使用独立的 A/B 最大跨度 `75`，避免通用跨度 `45` 只留下毛绒表面小碎片。两只熊全部标定后，脚本会：

1. 比较棕熊和白熊的 LAB 中位数。
2. 选择差异最大的通道。
3. 在中点两侧留出间隔并强制切开两个阈值。
4. 审计两个阈值不再重叠，并确认各自中位数仍在自己的阈值盒内。

成功时会输出：

```text
[bear] PASS brn=(...) wht=(...) overlap=0
```

若两只熊中位数过近或分离审计失败，两个熊阈值均不写入，最终只生成 partial 配置，不覆盖正式五色文件。

## 运行时识别强化

### 配置加载与固件兼容

- `/sd/color_thr.txt` 的所有数值使用显式整数循环解析，不依赖部分 OpenART 固件不稳定的生成器/嵌套推导式。
- 标定预览和正式程序使用预计算单应矩阵，不在板端动态求解 8×8 方程。
- 世界坐标使用目标底边中点作为地面接触点，避免上边角越过投影地平线。
- 标定日志的关键采样输出使用字符串拼接，规避固件的多参数 `%` 格式化异常。
- `find_color_target` 有运行时异常隔离；异常会节流输出 `[color] find_color_target error: ...`，不会让单帧错误直接终止主循环。

### 五色检测与跟踪

- 全局扫描一次处理五个阈值，重叠阈值产生的多 bit blob 被视为歧义，不按较小 ID 强行分类。
- 锁定单一颜色后使用局部 ROI 和连续性评分，降低其它候选抢框。
- 白熊使用 `margin=10` 合并碎片，并对输出框做 `2/3` 旧框、`1/3` 新框的平滑。
- 棕熊使用 `margin=12` 合并毛绒表面碎片。
- 色块候选继续执行像素数、面积、宽高比、密度、动态裁切和近处噪声过滤。

### 网球底部阴影防棕熊误报

若棕色小块满足以下关系，则按网球接触阴影丢弃：

- 位于网球下半部附近。
- 与网球横向重叠达到 `60%`。
- 面积不超过网球框的 `55%`。

即使主控锁定寻找棕熊，程序也会额外扫描网球阈值作为阴影参照，避免网球下方暗块被上报为 ID4。

### 动态地面裁切

- 主车和从车都使用横跨画面的 `5` 条窄竖带扫描蓝地顶部，并让目标搜索 ROI 从检测边界上方 `10 px` 开始。
- 主车至少要求 `3` 条有效带且横向跨度达到 `180 px`，使用稳健分位位置、黄线小间隙桥接、单帧升降限幅和 EMA 平滑。
- 从车至少要求 `2` 条有效带，对各带顶部取水平平均后做 EMA；它当前不是旧版左右端点斜裁切线，也不与主车的稳健分位算法完全相同。
- 两车都只拒绝完全位于裁切线上方的色块，跨过边界的目标仍保留。

### 搬运前避障扫描

主控命令 `0x06` 触发前方其它颜色扫描，结果通过 `0xC7` 包返回：

- `FRONT_SCAN_STABLE_FRAMES = 6`：`current_id / mask / count` 连续一致 6 帧时提前确认。
- `FRONT_SCAN_MAX_FRAMES = 12`：最多观察 12 帧，允许短暂抖动重新累计；到上限仍未连续稳定时发送第 12 帧的当前结果，60 FPS 下最长约 0.2 秒。
- 当前搬运目标会根据框 IoU/中心距离从其它颜色结果中排除。
- `front_obstacle_scan_test.py` 可用于脱离主控单独观察候选框、mask 和动态 ROI。

## `/sd/color_thr.txt` 格式

完整配置示例：

```text
exposure_us=1100
ground=20,55,-10,25,-70,-30
ground2=12,50,-18,12,-35,5
1,15,100,-35,5,-75,-20
2,20,80,15,90,-15,60
3,15,100,-60,-10,25,115
4,28,75,-15,35,0,70
5,55,100,-25,12,-15,55
```

颜色槽位固定为：

| ID | 目标 |
| --- | --- |
| `1` | 淡蓝沙包 |
| `2` | 红沙包 |
| `3` | 网球 |
| `4` | 棕色泰迪熊 |
| `5` | 白色泰迪熊 |

只有完整五色结果写入 `/sd/color_thr.txt`。未完成或冲突审计失败的结果写入 `/sd/color_thr_partial.txt`，正式配置保持不变；曝光首行除外，它会在自动曝光完成后立即更新。正式运行程序只有在 `/sd/color_thr.txt` 中读到完整 `1..5` 五个槽位时，才一并采用文件中的曝光、颜色和地面值；正式文件本身不完整时整组回退到内置参数。

## UART 数据包

主从目标数据均为 16 字节：

| 字节 | 内容 |
| --- | --- |
| `0-1` | 帧头 `0xAA 0x55` |
| `2` | 颜色 ID，`0` 表示无目标 |
| `3-4` | 世界 X，毫米，`int16` 小端序 |
| `5-6` | 世界 Y，毫米，`int16` 小端序 |
| `7-8` | 目标像素宽度，`uint16` 小端序 |
| `9` | 黄线标志，仅主车有效 |
| `10` | 位置状态，仅主车有效 |
| `11-14` | 保留字段，当前为 `0` |
| `15` | `data[2:15]` 累加校验和 |

搬运前扫描 `0xC7` 包为：

| 字节 | 内容 |
| --- | --- |
| `0-1` | 帧头 `0xAA 0x55` |
| `2` | 包 ID `0xC7` |
| `3` | 当前搬运目标 ID |
| `4` | 其它颜色 bit mask，bit0..bit4 对应 ID1..ID5 |
| `5` | 去重后的其它颜色数量 |
| `6` | `data[2:6]` 累加校验和 |

主车和从车收到 `0x07` 后都进入回库黄线模式，并在各自相机上独立主动判停。中央纵向窄条 ROI 为 `(150, 30, 20, 210)`，从 `y=30` 开始向下搜索，发现第一个黄色 blob 就立即记录中心 Y；下方横向窄条 ROI 为 `(0, 200, 320, 20)`，从右到左寻找停车竖线。两处像素和面积门槛均为 `5`，横线 Y 不检查形状、左右配对或连续帧。为避免小车前冲时横线下降进入停车 ROI 造成误判，当横线 Y 位于停车 ROI 上下 `3 px` 范围内时暂停本帧 X 判停；其它帧的停车候选高度至少为 `8 px`，宽度不超过高度的 `3` 倍。候选中心 X 严格大于 `200` 后锁存停车标志，直到退出回库模式；停车状态不依赖后续横线 Y 是否有效，两车都会持续通过各自的 `0xC8` 包发送。返回格式为：

| 字节 | 内容 |
| --- | --- |
| `0-1` | 帧头 `0xAA 0x55` |
| `2` | 包 ID `0xC8` |
| `3` | 状态位：bit0=`y_valid`，bit1=`stop`；可同时置位 |
| `4-5` | 黄线 Y 坐标，`uint16` 小端序；无效时为 `0` |
| `6` | `data[2:6]` 累加校验和 |

两车的回库黄线 LAB 阈值按各自相机保留，不应互相照抄。

## 常见日志与排错

| 日志 | 含义与处理 |
| --- | --- |
| `swap clear n/8` | 正在确认上一目标完全离场；达到 8/8 后再放下一目标 |
| `box jump, rebase n/3` | 红袋框切换到新位置，等待新位置稳定 |
| `模型有目标但新阈值找不到色块` | 阈值覆盖不足、目标过暗或颜色被地面切割；保持目标不动观察自动重采 |
| `色块框面积只剩模型框很小一部分` | 阈值只覆盖局部纹理；检查 LAB 跨度、地面冲突和取样框 |
| `[bear] ... overlap=0` | 棕熊与白熊最终阈值已强制分开 |
| `正式配置未覆盖` | 五个槽位不完整，当前只写 partial 文件 |
| `[color] find_color_target error:` | 运行端捕获到固件类型异常；保存完整一行用于定位，主循环会继续 |

如果画面框和日志行号与本文版本不一致，首先确认 IDE/SD 上运行的不是旧脚本或带 `(2)(1)` 后缀的重复副本。
